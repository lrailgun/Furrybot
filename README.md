# Furrybot 2.3.4 — Absurd Edition

Нативный Discord-бот для генерации абсурдных, но связных антропоморфных персонажей: имя, вид животного, класс D&D, мировоззрение, статы Point Buy 27, характер, предыстория, нелепая способность, квадратный аватар. Текст и изображения создаются только через облачный Cloudflare Workers AI. Хосту не нужны Docker, GPU или локальные модели.

## Установка Linux (systemd)

Python 3.10+, Git, systemd и модуль venv. Для Debian/Ubuntu:

```bash
sudo apt update
sudo apt install -y git python3 python3-venv

git clone https://github.com/lrailgun/Furrybot.git
cd Furrybot
sudo bash install.sh
sudo furrybot
```

Установщик создаёт отдельного непривилегированного пользователя `furrybot`, рабочую копию `/opt/furrybot` (клонирует `main` из официального репозитория), версионное виртуальное окружение и службу `furrybot.service`. Исходная копия в домашнем каталоге после установки не нужна. Команда `furrybot` устанавливается в `/usr/local/bin`. Служба включается в автозапуск, но первоначально не запускается до настройки секретов.

В меню выбери **6. Задать секреты**. Введи Discord bot token, Cloudflare Workers AI API token, Cloudflare Account ID. Токены вводятся без отображения, не передаются в аргументах процесса и не сохраняются в Git. Затем выбери **2. Запустить**. При изменении конфигурации перезапусти сервис.

## Cloudflare Workers AI (без OpenAI)

1. В [Cloudflare Dashboard](https://dash.cloudflare.com/) открой Workers AI → Use REST API.
2. Create a Workers AI API Token → Create API Token → Copy API Token. Это `CLOUDFLARE_API_TOKEN`.
3. В Get Account ID скопируй `CLOUDFLARE_ACCOUNT_ID`. При ручной настройке токена нужны Account / Workers AI / Read и Edit для своего аккаунта.
4. Оставайся на Workers Free: 10 000 Neurons в сутки, сброс в 00:00 UTC. На Workers Paid превышение квоты платное. [Документация](https://developers.cloudflare.com/workers-ai/get-started/rest-api/) · [Тарифы](https://developers.cloudflare.com/workers-ai/platform/pricing/).
5. `sudo furrybot --secret` → введи новые реквизиты → `sudo furrybot --start`.

По умолчанию текст генерирует `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, аватар — `@cf/black-forest-labs/flux-2-klein-4b` (4 фиксированных шага). Черновик сохраняется только при успешной генерации текста и аватара, прежние WebP-аватары по-прежнему доступны.

### Обновление с 2.0 (OpenAI)

Сначала останови службу: старый updater иначе попытается запустить новую версию до ввода Cloudflare-реквизитов и может откатить обновление.

```bash
sudo furrybot --stop
sudo furrybot --update
sudo furrybot --secret
sudo furrybot --start
```

При сохранении конфигурации CLI удалит устаревшее поле OpenAI. Старые стандартные модели заменяются новыми; если ранее были указаны другие модели, настрой их через `sudo furrybot --config`. База персонажей, роли, черновики и Discord-токен сохраняются.

## Discord

Discord Guild ID больше не требуется: пригласи бота штатным способом на любой сервер и выполни `!furry install`. Каналы, роли, черновики и принятые фурсоны хранятся отдельно для каждого сервера. Старое поле `DISCORD_GUILD_ID` в конфигурации игнорируется, а при следующем сохранении настроек удаляется. Личные сообщения бот игнорирует.

1. Создай приложение и бота в [Discord Developer Portal](https://discord.com/developers/applications).
2. В разделе Bot включи **Message Content Intent**. Привилегированный Members Intent не требуется.
3. Пригласи бота на сервер со scope `bot` и правами View Channels, Send Messages, Embed Links, Attach Files, Read Message History, Manage Channels, Manage Roles. Права Administrator боту не нужны. Его роль должна стоять выше роли участника, которую он будет выдавать.
4. В существующем текстовом канале от аккаунта с Discord Administrator напиши `!furry install`.
5. Бот создаст канал `#фуррификация`, панель с постоянными кнопками, роли `Его пушистое величество` и `Пушистый ребёнок природы` (или использует уже зарегистрированные ID/однозначно совпадающие названия). Роли создаются без серверных привилегий. Назначь `Его пушистое величество` администраторам, которым разрешено менять принятые фурсоны.

Панель доступна участникам, обычные сообщения в новом канале отключены. Администраторы могут повторять установку: сохранённые ID канала, сообщения и ролей переиспользуются. При удалении объекта установка восстановит его. Нельзя автоматически выдавать роль участника, имеющую серверные права, управляемую интеграцией или расположенную выше роли бота. Доступ к отдельным каналам можно задавать через permission overwrites роли.

### Цвета и назначение администратора

Повторный `!furry install` применяет цвета к новым и существующим ролям: `#FFB668` для «Его пушистое величество», `#E74C3C` для «Пушистый ребёнок природы». Роль бота должна быть выше обеих ролей, если требуется их изменение.

Настроенный администратор бота (Discord ID `221764587060461569`) получает роль при собственной установке или по явной команде администратора сервера `!furry install --grant-admin`. Проверяется наличие участника, его существующее право Discord Administrator, отсутствие серверных прав у выдаваемой роли и иерархия. При успехе отдельное публичное уведомление не публикуется; назначение записывается в журнал и Discord Audit Log. Если назначение невозможно, обычное сообщение установки напоминает о необходимой роли, не раскрывая результат поиска участника. На сторонних серверах обычная установка не назначает роль постороннему аккаунту автоматически.

### Если кнопки не отвечают

Проверь, что поле Interactions Endpoint URL в General Information приложения Discord пустое: бот получает взаимодействия через Gateway. Смотри `sudo furrybot --logs` во время нажатия. В журнале должны появляться Interaction received и Interaction acknowledged. С версии 2.3.2 все кнопки Furrybot обрабатываются общим маршрутизатором событий, независимо от срока жизни View и рестартов. В журнале Interaction dispatch показывает возраст события, Interaction acknowledged — длительность ACK, Interaction expired before ACK — задержку и ошибку Discord 10062. Если ACK не успел в три секунды, это отдельная проблема доставки события или HTTP-запроса, а не Cloudflare. Первичный приватный defer выполняется до работы с БД или Cloudflare.

### Изображения и сюрреалистический юмор

С версии 2.3.3 приватный черновик — одно Markdown-сообщение с аватаром во вложении и кнопками. При успешной перегенерации редактируется это же сообщение, старое вложение заменяется новым. При генерации сразу отображается «Awwtysm Furry Bot определяет вашу судьбу. Пожалуйста, подождите...». При перегенерации прежнее вложение сохраняется до успеха. При ошибке статус заменяется сообщением об ошибке, прежний черновик сохраняется. Общий дедлайн для текста и аватара — 300 секунд; индивидуальные HTTP-дедлайны остаются 90/180 секунд. В журнале фиксируются этапы Generation stage (text, avatar, delivery), HTTP-статусы и длительности запросов Cloudflare, без токенов. Принятие обновляет сообщение и убирает кнопки. Старые отдельные вложения из прежних версий и ранее открытые дубликаты автоматически не удаляются; их можно закрыть через Dismiss message. Повторное открытие через общую панель может создать новую приватную карточку. Каноничный промпт `AVATAR_STYLE` находится в `style.py`: ретро-мультяшная графика, толстый тёмный контур, крупные простые формы, плоские цветовые пятна, двухтоновые тени, матовая бумажная фактура. Палитра и фон индивидуальны. Только один персонаж, квадратный портрет, без коллажа и агитационных символов. С 2.3.1 кадрирование фиксировано: голова занимает около 70% ширины, грудь обрезана нижней границей, плечи доходят до боковых краёв, ноги и хвост за кадром. Стиль конкретизирован: угловатые крупные пряди, тёмный контур, светлая обводка силуэта, резкие двухтоновые тени, плоские цветовые пятна, бумажная зернистость, графический фон. Переменная часть — английское описание внешности, без указаний композиции. В журнале Avatar generation записывается фактическая модель, количество референсов и запрошенный размер. FLUX.2 Klein 4B получает два настоящих референса рисовки из assets вместе с каноничным текстовым промптом через multipart REST API, размер результата 1024×1024. Референсы — фрагменты утверждённой пользователем подборки, а не шаблон персонажа. Старая модель FLUX.1 Schnell автоматически заменяется при чтении конфигурации; значение IMAGE_STEPS сохраняется для совместимости, но Klein 4B использует фиксированные четыре шага. Точное совпадение стиля зависит от модели. Для проверки более качественного варианта через `sudo furrybot --config` можно задать IMAGE_MODEL=`@cf/black-forest-labs/flux-2-klein-9b`: он также получает оба референса. 9B существенно дороже по Neurons; 4B остаётся стандартом, чтобы сохранить бесплатную квоту. Не переходи на платный тариф.

Текст создаётся в два облачных этапа: короткий запрос трёх комических завязок и пяти вариантов имени, затем запрос полноценной карточки. Для каждой генерации выбирается один из семи подходов к именованию. Недавние полные имена исключаются из кандидатов и проверяются без учёта регистра, пробелов и различия е/ё; повторное имя требует исправления карточки. Дополнительного API-запроса ради имён нет. Сатира строится на конкретной мотивации, поступке и последствиях, а не на случайном сочетании предметов. Тематическая область и комедийный механизм служат необязательными подсказками. Недавние биографии не передаются целиком: только идентичности и частотные слова, чтобы уменьшить копирование. История сохраняет до 40 успешных генераций на сервер. Анти-повторы остаются мягкими; до трёх попыток формирования карточки, при неудачном улучшении возвращается валидная версия. Некорректный ответ этапа завязок не блокирует генерацию карточки, ошибка API останавливает запрос. Дополнительный короткий текстовый запрос расходует бесплатную квоту. Текстовая модель и провайдер не изменились; локальной генерации нет. С версии 2.3.0 биография должна содержать 400–850 символов (целевой объём 450–750) и 4–6 предложений по промпту. Слишком короткий текст повторно запрашивается, а не выдаётся как готовая карточка. Повторный запрос может расходовать квоту. Старые персонажи не изменяются.

## Как работает фуррификация

- **Создать / продолжить**: генерирует персонажа, если его ещё нет, либо показывает текущий черновик или принятую фурсону.
- Черновик и его аватар видны только участнику. **Ещё вариант** заменяет черновик после успешной генерации текста и аватара. Нет суточного лимита и кулдауна; только один запрос на участника и глобальное ограничение одновременных операций (по умолчанию 2). Каждый вариант расходует бесплатную квоту Cloudflare Workers AI. При исчерпании квоты на Workers Free запросы прекращаются до 00:00 UTC; не переходи на Workers Paid.
- **Принять навсегда** атомарно сохраняет конкретную ревизию, удаляет черновик, блокирует пользовательскую перегенерацию и выдаёт роль **Пушистый ребёнок природы**. Если Discord не выдал роль, принятый персонаж остаётся заблокированным: после исправления прав нажми **Моя фурсона**, чтобы повторить выдачу.
- Старые кнопки не могут принять новый черновик. Черновики переживают перезапуск. Новые кнопки содержат ID сервера, владельца и ревизию черновика; после рестарта они работают без восстановления View, пока Discord позволяет нажимать исходное сообщение. Старые кнопки из версий до 2.3.2 предлагают открыть карточку заново. Прежняя ревизия не может принять новый вариант.
- После принятия обычный участник не может изменить или удалить персонажа через команды или кнопки. Администратор с ролью **Его пушистое величество** может заменить принятую фурсону через `!furry regenerate @участник`. Старый персонаж сохраняется при неуспешной генерации. Для административной замены требуются оба признака: Discord Administrator и сохранённый ID специальной роли.
- Аватар выдаётся файлом: бот не может менять личный Discord-аватар пользователя.

### Команды Discord

| Команда | Действие |
|---|---|
| `!furry` / `!furry help` | Справка и ссылка на панель |
| `!furry install` | Создание / восстановление канала, панели и ролей; Discord Administrator |
| `!furry profile [@участник]` / `!furry fursona` | Принятая карточка |
| `!furry avatar [@участник]` | Принятый аватар |
| `!furry roster` | До 20 последних принятых персонажей |
| `!furry species` | До 25 наиболее частых видов |
| `!furry regenerate @участник` | Административная замена принятого персонажа |

`!furry generate`, `!furry reroll`, `!furry accept` направляют в интерактивный канал: приватные черновики доступны только через кнопки. Старые slash-команды v1 удаляются на соответствующем сервере при `!furry install`, если доступна синхронизация команд приложения.

## CLI

```text
furrybot                  # интерактивное меню
furrybot --help
furrybot --version
furrybot --status
sudo furrybot --start
sudo furrybot --stop
sudo furrybot --restart
sudo furrybot --logs
sudo furrybot --secret     # токены + Cloudflare Account ID
sudo furrybot --config     # модели, шаги изображения, параллельность, названия
sudo furrybot --check-update
sudo furrybot --update
```

Можно писать и без `--`: `sudo furrybot update`. Меню управления удобнее запускать через `sudo furrybot`. Секреты хранятся в `/etc/furrybot/config.json` (root:furrybot, 0640), база и аватары — в `/var/lib/furrybot/fursonas.sqlite3` (каталог 0700). Изменение названий в настройках применяется к вновь создаваемым объектам; уже зарегистрированные ID не переопределяются по имени.

Обновление берёт `origin main`, отказывается от грязного рабочего дерева и расходящихся веток. Перед переключением устанавливает зависимости в отдельный venv. Затем останавливает ранее запущенный сервис, выполняет fast-forward, запускает тесты, переключает venv и unit, восстанавливает предыдущее состояние работы сервиса. При ошибке переключения/тестов/запуска пытается откатить код, venv и unit. Секреты и БД не входят в Git. Автоматическая проверка запуска не гарантирует успешную авторизацию Discord или работу Cloudflare Workers AI; проверь журнал. Откат не откатывает возможные миграции БД. Старые окружения остаются в `.venvs` для восстановления.

### Миграция с v1 (Docker)

Новая установка не переносит данные автоматически. Останови старый контейнер, сделай резервную копию SQLite (с учётом WAL), перенеси согласованный файл БД в `/var/lib/furrybot/fursonas.sqlite3` до запуска новой службы и установи владельца `furrybot:furrybot`, права 0600. Введи токен Discord и новые реквизиты Cloudflare через CLI. Существующие записи считаются принятыми и блокируются от пользовательской перегенерации; роли можно получить кнопкой «Моя фурсона». Не запускай обе версии одновременно.

## Тесты

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests
```

Тесты не требуют API-ключей. Реальная генерация, Discord-кнопки, иерархия ролей и systemd требуют проверки на целевом сервере.
