# Furrification Engine v1.2 — Absurd Edition

Discord-бот для добровольной фуррификации участников одного сервера: оригинальная фурсона, D&D-подобная карточка первого уровня и квадратный аватар. Все творческие данные (включая значения характеристик) генерируются облачными моделями OpenAI. На хосте работают только Discord-клиент, HTTP-запросы, валидация, форматирование карточек и SQLite. Никаких локальных моделей, генераторов изображений или GPU.

## Тон генерации: связный абсурд

Персонажи — антропоморфные ходячие недоразумения, а не стандартные герои фэнтези. Предыстория строится вокруг нелепой предпосылки, причинно-следственной эскалации и финального поворота, изложенных с невозмутимой серьёзностью. Вид, класс, происхождение, характер, способность и визуальный атрибут связаны общей шуткой. Промпт требует варьировать комические механизмы и избегать бессвязных мемов. Аватар тоже подчёркивает характер героя. Всё это по-прежнему генерируется через облако; механика D&D и команды не изменены. Стиль проверен на уровне инструкций, но качество реальных ответов облачной модели без ключа не измерялось.

## Команды

| Команда | Действие |
| --- | --- |
| `/furrify` | Создать персонажа и опубликовать карточку; повторный вызов возвращает существующую карточку без API-запросов. |
| `/fursona [user]` | Карточка зарегистрированного персонажа участника. |
| `/reroll confirm:true` | Заменить своего персонажа и аватар. Старая карточка сохраняется до успешной генерации новой. |
| `/avatar` | Получить исходный WebP 1024×1024 для установки на профиль вручную. |
| `/species` | Распределение видов на сервере. |
| `/roster [page]` | Реестр персонажей, по 10 на страницу. |
| `/forget confirm:true` | Удалить свою карточку и аватар из базы бота. Уже опубликованные сообщения Discord не удаляются. |

Бот не читает переписку, не анализирует профиль участника и не фуррифицирует его без его участия. `/fursona` только читает уже созданную публичную карточку. Бот не меняет настоящий аватар Discord другого пользователя: Discord не предоставляет ботам такой возможности. Участник может установить полученную картинку сам.

## Установка

1. Создай приложение в [Discord Developer Portal](https://discord.com/developers/applications), раздел Bot — получи токен. Не публикуй его и не коммить `.env`.
2. В Installation включи Guild Install, scopes `bot` и `applications.commands`. Разрешения бота: View Channels, Send Messages, Embed Links и Attach Files (если используются треды — Send Messages in Threads). Administrator не требуется. Установи приложение на свой сервер через предоставленную ссылку установки. Привилегированные Gateway Intents не нужны.
3. В Discord включи Developer Mode (User Settings → Advanced), скопируй ID сервера через контекстное меню.
4. Получи ключ проекта на [OpenAI API Platform](https://platform.openai.com/api-keys), включи API billing. Подписка ChatGPT не включает API-расходы. Для выбранной модели изображений может потребоваться верификация организации. Если для использования API требуется участие родителя/опекуна, соблюдай условия провайдера.
5. Клонируй репозиторий и создай файл `.env` из шаблона:

```bash
git clone https://github.com/lrailgun/Furrybot.git
cd Furrybot
cp .env.example .env
```

Windows PowerShell: `Copy-Item .env.example .env`.

Заполни `DISCORD_TOKEN`, `DISCORD_GUILD_ID`, `OPENAI_API_KEY` своими значениями. Не отправляй эти ключи в чат.

### Docker Compose (рекомендуемый способ)

```bash
docker compose up -d --build
docker compose logs -f bot
```

При старте бот регистрирует команды на указанном сервере (guild-scoped). Docker автоматически перезапускает процесс при сбое. База и изображения хранятся в постоянном томе `fursonas`. Не используй `docker compose down -v`, если хочешь сохранить персонажей.

### Обновление с GitHub (Linux / Bash)

```bash
./update.sh --check   # проверить новые коммиты
./update.sh           # скачать и развернуть обновление
docker compose logs -f bot
```

Скрипт работает в том же каталоге клона, только на ветке `main`: проверяет отсутствие локальных изменений отслеживаемых файлов, загружает `origin/main`, разрешает только fast-forward, собирает новый образ до замены контейнера и запускает его. `.env` и том `fursonas` сохраняются. При ошибке сборки прежний контейнер не заменяется; повторный запуск скрипта пересобирает образ даже при актуальном исходном коде. Проверка `--check` не определяет версию запущенного контейнера, только исходников. Автоматический откат и проверка подключения к Discord не реализованы. Не запускай параллельно два обновления. Остановка: `docker compose down`. Не используй `down -v`.


### Без Docker

Python 3.11 или новее, предпочтительно 3.12:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

Windows PowerShell: вместо `source` используй `.venv\Scripts\Activate.ps1`.

## Конфигурация

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TEXT_MODEL` | `gpt-4.1-mini` | Модель с поддержкой Responses API и strict Structured Outputs. |
| `IMAGE_MODEL` | `gpt-image-1.5` | Модель Images API с поддержкой WebP и размера 1024×1024. |
| `IMAGE_QUALITY` | `medium` | `low`, `medium`, `high`, `auto`; влияет на стоимость и задержку. |
| `DAILY_LIMIT` | `20` | Общий лимит попыток создания/замены в сутки (UTC). |
| `COOLDOWN_SECONDS` | `600` | Интервал между попытками одного участника (в секундах). |
| `MAX_PARALLEL` | `2` | Максимальное число одновременно выполняемых генераций. |
| `DATABASE_PATH` | `data/fursonas.sqlite3` | Файл SQLite. В Docker оставь значение по умолчанию. |

Одна успешная генерация обычно требует одного текстового запроса и одного запроса изображения. При невалидном тексте возможен один дополнительный запрос. При ошибке лимит попыток всё равно расходуется: провайдер мог уже начислить оплату. Установка лимита не заменяет настройки бюджета и мониторинга API-проекта. Повторное отображение персонажей, получение аватара и статистики не вызывают OpenAI API.

## Механика

12 базовых классов D&D, 9 мировоззрений, 6 характеристик. Модель выбирает вид, имя, происхождение, характер, предысторию, сюжетную особенность и внешний вид; затем отдельная облачная модель создаёт оригинальный портрет по описанию. Перед генерацией картинки проверяется схема и Point Buy на 27 очков (8–15 без бонусов происхождения). Модификаторы считаются по формуле D&D `(score - 10) // 2`. Это генератор карточек, а не полный симулятор D&D: нет боя, заклинаний, инвентаря, расовых бонусов и бросков кубиков. Особенность вида — сюжетная, не официальная механика. Рейтинг по сумме статов намеренно заменён реестром: Point Buy предназначен для баланса, а не соревнования по сумме характеристик.

Разнообразие видов обеспечивается подсказкой модели и списком до 20 недавних вымышленных персонажей. Уникальность имён и равномерная вероятность видов не гарантированы: это не генератор случайных чисел. Поля вид и имя валидируются по длине, не по таксономическому каталогу. Модель может придумать фантастический вид.

## Данные и ограничения

- В облако передаются только инструкции и вымышленные данные персонажей (до 20 недавних комбинаций имя/вид/класс), не Discord ID, ники, фото или история переписки. Для Responses API установлен `store:false`; это не означает полного отсутствия хранения у провайдера.
- SQLite хранит ID сервера, ID участника, JSON карточки, байты аватара, отметку времени, квоты и cooldown. `/forget` удаляет карточку и аватар из активной базы, но старые сообщения, резервные копии и короткоживущие записи квот остаются отдельно. SQLite-файл не шифруется; ограничь доступ к нему.
- Публичные карточки видят участники канала. Используй только на сервере, где участники согласны с такой механикой.
- Для генерации нужен исходящий HTTPS к OpenAI и Discord и доступ к Discord Gateway. В отсутствие API бот не подставляет локальный генератор.
- Не запускай несколько экземпляров бота с одной базой. Непосредственная интеграция с Discord и OpenAI требует действующих ключей и доступной модели; она здесь не проверена.

## Тесты

```bash
python -m unittest discover -s tests -v
python -m py_compile bot.py engine.py storage.py
```

Тесты используют подставные ответы облачного API, не требуют ключей и не тратят деньги. Проверяются схема, Point Buy, исправление невалидной карточки, отказ модели, обработка изображения, SQLite и ограничения генерации. Синтаксис бота проверен, но импорт/регистрация slash-команд и реальные сетевые запросы не запускались в среде сборки (discord.py там не установлен).
